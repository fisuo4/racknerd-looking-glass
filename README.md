## Looking Glass 到底能测什么？和测试 IP 有什么区别

Looking Glass 是跑在机房里的一张网页，测的是「机房 → 你」这个方向：你在页面上发起 ping、traceroute、MTR，或者下载测速文件，流量从 RackNerd 的机房流向你的真实 IP。RackNerd 官方博客对它的定位说得很直白：以前主机商只给一个测试 IP 和测试文件，只能单向测延迟；有了 Looking Glass，两个方向都能测，才能对延迟、路由路径和速度有完整判断。

测试 IP 测的是反方向——你在本地 ping 那个 IP，看「你 → 机房」的延迟和丢包。两边路由不一定对称，去程快回程慢的情况真实存在，所以买 VPS 前正确的做法是两个都测，而不是只测一边。

一个常被忽略的细节：各节点的测速文件规格并不统一。比如亚特兰大页面提供 10MB、100MB、1GB 三档，洛杉矶 DC-05 给的是 25MB、50MB、100MB、1000MB 四档。下载前先看页面上实际列出的文件，别默认每个机房都一样。另外大部分 Looking Glass 页面顶部有地点切换器，测完一个机房直接在下拉菜单里切下一个就行，不用开一排浏览器标签。

## 六步测完一个机房，别只 ping 一下就下结论

1. 打开候选机房的 Looking Glass 页面，点输入框下方的 "My IP" 按钮，自动填入你的公网 IP。
2. 选 Ping，跑一次，记下平均往返毫秒数。
3. 换两三个候选机房，重复同样操作，横向比较平均值。
4. 某个节点 ping 异常偏高时，改用 MTR——它结合了 ping 和 traceroute，能看到每一跳的丢包，用来判断问题出在中间哪段路由。
5. 从候选节点下载 100MB 测试文件，看真实下载速度；带宽很大再上 1GB 文件。
6. 关键的一步：换个时间再测一遍，尤其是晚高峰。

为什么第 6 步不能省？不同时段的结果可能差很多，晚高峰的表现才接近你之后真实使用的状态。测下载速度之前，把本机占带宽的东西全关掉——迅雷、Steam、挂着视频的浏览器、代理软件，否则测出来的是你自己电脑的混乱状况。

解读数字时有条简单的分界线：两个机房差 5ms，肉眼完全无感，不用纠结；差到 30ms 和 180ms 这种量级，就是真实差距了，不该为了几块钱差价选延迟差的那个。参考基线大致是：低于 50ms 几乎即时，50–100ms 对多数网站和应用够用，超过 150ms 做交互类工作会明显感到卡顿。

## 国内用户怎么看结果：多少毫秒算能用

先给结论：美国西海岸到中国大陆，平均延迟在 130–180ms 之间属于优秀表现；如果只看「能不能接受」，150–200ms 以内的美西节点做普通建站都没问题，平均 ping 超过 250ms 就不太适合国内访问了。你所在地区（比如广东电信）的具体数值，比全国平均值更值得看。

具体到机房选择，国内用户的第一梯队是洛杉矶 DC-02、DC-03、圣何塞、西雅图这几个美西节点。DC-02 是 Multacom 机房，走电信 CN2 加联通的混合线路（官方标 Asia Optimized），虽然算不上 CN2 GIA，但基本是直连，访问 Google 出验证码的概率也相对低。DC-03 用的是 ColoCrossing 机房，优势是已经上线免费原生 IPv6。次选达拉斯、芝加哥、纽约、阿什本——这些适合服务北美或外贸场景。

顺便说下 IPv6：洛杉矶（DC-03）和法国（斯特拉斯堡）机房可以下单后开工单，免费申请最多 100 个 IPv6 地址，其他节点暂不支持。需要 IPv6 的话，机房选择基本就被这两个锁定了。

两个进阶工具值得配合用：

- **itdog.cn 的 ping 测试**：输入测试 IP，能模拟全国不同省份、不同运营商（电信/联通/移动）访问这个 IP 的结果，比你自己一个人的网络有代表性。
- **ping.pe**：持续测试加路由分析。图表里绿色代表顺畅，红色方块越多丢包越严重——丢包会直接表现为网页打不开、SSH 掉线。往下翻能看到 MTR 数据，重点看最后几跳从国内哪个出口出去（北京、上海还是广州），以及有没有绕道日本或欧洲。直连通常优于绕路。

想在更接近真实的条件下验证，就锁定本地晚高峰 8 点到 11 点，用 MTR 把候选机房各跑一遍。
